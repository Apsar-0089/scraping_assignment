## Which parts were AI-assisted

Essentially all of the initial code was generated by Claude in one pass, following the reference document's stage order:

- `config.py`, `scrapers/base_scraper.py`, `scrapers/books_scraper.py`, `scrapers/quotes_scraper.py`
- `processing/cleaning.py`, `processing/validation.py`, `processing/deduplication.py`
- `main.py` (pipeline, CLI, logging, summary report)
- `tests/test_cleaning.py`, `tests/test_validation.py`, `tests/test_deduplication.py`
- `README.md`, `requirements.txt`, `.gitignore`

Design decisions the AI proposed that I adopted after reviewing them:

- Pulling URLs, delays and paths into a separate `config.py`
- Scrapers return raw dicts and `clean_record()` maps them onto the common model (keeps scraping and transformation fully separate)
- `source_url` for quotes = listing page URL (not author page)
- Duplicates removed rather than flagged, with counts in the summary
- An extra `missing_author` validation rule for quotes beyond the five rules in the brief
- `--fetch-details` as an opt-in flag instead of always hitting 1,000 detail pages

## Questions I can answer about this code

*(Prepare these — the brief says they'll be asked.)*

- Why Requests + BeautifulSoup and not Selenium/Scrapy → server-rendered HTML, no JS, ~60 pages; a browser adds cost for nothing.
- How pagination works → `BaseScraper.scrape()` follows `li.next > a` with `urljoin` until it is missing; no page counts anywhere.
- How failed requests are handled → `urllib3.Retry` for 429/5xx with backoff; anything that still fails is logged and that source stops; the other source is wrapped separately in `main.py` so it still runs.
- How missing fields are handled → `select_one()` + `None` check per field; the value becomes `None`, never a crash; invented placeholders are never written.
- How dedup works → fingerprint of (source + title) or (source + author + first 50 chars), lowercased, punctuation stripped, whitespace collapsed, SHA-256; first seen wins.
- What I'd change for production → concurrency with a rate limiter, checkpoint/resume, a database sink instead of CSV, scheduled runs with alerting on `failed_requests > 0`, and monitoring selector drift.
